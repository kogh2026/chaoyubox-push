## 1. 任务本质

"证卡拼版助手（增强模型）"做的是：**输入整张身份证照片 → 定位卡片并矫正 → 定位卡内人像区域 → 输出 295×413 标准证件照**。
识别链路包含：卡定位+透视矫正、人像分割/抠图、构图居中、以及（爱印具备）卡面文字 OCR 字段提取。

> 关键点：超誉的"增强模型"用的就是**爱印同款 FP32 卡证矫正 ONNX**（输入 `[1,3,768,768]`，已解密本地化）。因此**在卡矫正几何层面两者同源**，差异只可能出现在① 退化输入下的抠图后处理、② 多卡/复杂版面检测、③ OCR 字段提取、④ 是否走了模型还是退化到弱 CV。

## 8. 优点与缺点总结

### 超誉优点
1. 已采用与爱印**同源 FP32 模型**为识别主路径，卡矫正/人像提取几何已达持平。
2. **覆盖更全**：51/51 无静默丢弃；模型无检出时回退 CV 并标记"需检查"而非丢文件。
3. 已内置 CV 兜底 + Worker 常驻 + 120s 超时重建，防 onnxruntime 挂死。
4. 模型已解密本地化、仓库自包含，可自由迭代，无加密黑盒。

### 超誉不足（重点）
1. **无 OCR 字段提取**——最大短板，字段完整性为 0，无法按姓名/身份证号命名或结构化。
2. **退化输入抠图质量**略逊：模糊/低对比样本偶发截断暗条、边缘羽化不足（见第 4 节模糊组）。
3. **多卡/复杂版面检测**弱于爱印（自研 cardDetect.ts vs 爱印 OpenCV.js 多卡 worker），遮挡+多卡场景鲁棒性存疑。
4. 旧版 CV-only 曾导致需检查率 40%——已由方案 A 修复，但需回归确认线上已生效。
5. 缺"打印增强/磨皮/网点"等图像增强开关（爱印生产级输出的一部分；注意爱印过度磨皮有塑料感，不宜照搬）。

### 爱印优点 / 缺点
- 优点：同源模型 + 专用多卡检测与抠图后处理（退化输入更稳）；具备 OCR/字段命名；打印增强/水印等生产级输出；商业闭环体验好。
- 缺点：闭源、模型加密（已被动解密）；**偶发漏检静默丢弃文件**（本批 1 张）；过度磨皮导致塑料感；绑定其生态。

## 9. 改进建议与优先级排序

| 优先级 | 改进项 | 具体做法 | 预期收益 |
|---|---|---|---|
| **P0** | 接入 OCR 字段提取 | 复用 PaddleOCR 或已解密资产中的文字识别模型，读取姓名/身份证号/住址，支持"按证件姓名命名"与结构化导出 | 补齐字段完整性 0→多字段，消除最大体感差距 |
| **P0** | 确认模型主路径已生效 | 用当前构建对 51 张重跑 `bench_card_model.py` 全量，验证"需检查"≈0、输出为模型版 | 确证方案 A 已消除历史 CV 差距 |
| **P1** | 退化输入抠图增强 | 针对模糊/低对比样本优化人像分割与边缘羽化，消除底边截断暗条伪影 | 模糊组由 3.5→4+，追平爱印 |
| **P1** | 多卡/复杂版面检测对齐 | 引入 OpenCV.js 或 onnx 多卡检测 worker，替代单卡 cardDetect.ts | 降低遮挡/多卡漏检风险 |
| **P2** | 图像增强开关 | 提供自动亮度/对比/磨皮（克制，避免塑料感）对标"打印增强" | 提升过亮/低对比样本观感 |
| **P2** | 漏检兜底而非静默丢弃 | 模型无检出时明确标记"需检查"并保留原图，避免像爱印那样丢文件 | 提升批量可靠性 |
| **P3** | 输出一致性维护 | 背景合成/尺寸规范已持平，保持回归 | 稳定交付 |

## 10. 结论与下一步

1. **人像提取质量**：模型接入后，超誉与爱印**整体持平**（正常/过亮/低对比均 5/5、4/4、4/4；仅模糊组爱印略优 0.5 分）；覆盖率超誉更优（51/51 vs 50/51）。
2. **真正差距**不在裁切几何，而在 **① OCR 字段提取（0 vs 多字段）**、**② 退化输入抠图细节**、**③ 多卡/遮挡鲁棒性**。
3. **历史误判根源**：用户 10-28 实测时超誉尚未接入模型，以 CV 为主路径（需检查率 40%），故落后；方案 A 已修复。
4. **建议下一步**：用当前模型版构建对 51 张全量重跑基准，得到确定性当前指标；并优先落地 P0 的 OCR 字段提取。
