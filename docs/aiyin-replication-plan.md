# 爱印「证件拼版助手」源码梳理 与 React 1:1 复刻方案

> 版本：2026-10-29 · 范围：桌面版爱印（v0.5.0）的证件照 / 图片拼版 / 打印链路
> 方式：只读静态分析 + 干净实现（clean-room）。解密产物仅在 `aiyin_decrypted_assets/` 内，
> 原始安装文件零改动，未绕过任何运行时保护，产物不用于再分发。

---

## 一、源码定位：先解决「读得到」的问题

爱印的渲染层不是普通 Electron 打包，静态资源全部加密，直接 `ls` 只能看到一堆无法阅读的二进制。

### 1.1 资产加密格式（技术壁垒本体）

```
文件 = "AYE1"(4B) + IV(12B) + GCM tag(16B) + 密文
算法 = AES-256-GCM
密钥 = hkdfSync("sha256", M7hex, salt="aiyin/desktop-asset/v1", 32)   // M7 硬编码 64 位 hex
IV   = HMAC-SHA256(key, 相对路径 ‖ 0x00 ‖ sha256(明文))[0:12]
AAD  = 资源相对路径
```

主进程用 `registerStreamProtocol` 注册自定义 scheme，按请求路径解密后流式下发；白名单只有
`assets/*.js|css`、`assets/runtime/*.bin`、`vendor/*.js`，**明文资产会被拒收**（plaintext-refused）。
这也是为什么「改 dist 里的 js 再启动」不生效 —— 校验不过就 404。

想读源码就必须按同一套 KDF/IV/AAD 重算并校验 GCM tag。本项目已完成 101 个文件的解密
（tag 全部校验通过），产物落在 `aiyin_decrypted_assets/`。

### 1.2 读完源码后的第一个判断

**爱印的私有资产只有两份模型权重（抠图、匀肤）**。其余全部是：

- 公开模型：MediaPipe `selfie_multiclass_256x256.tflite`、Face Landmarker 官方任务包；
  抠图网络经算子直方图比对，与开源 MODNet 同构（215/215 初始化器对应、参数 6.460M 一致，
  仅权重为 fp16 并含 65 个 Cast）；
- 开源库：onnxruntime-web、mediapipe tasks-vision、jspdf、opencv.js；
- 纯业务逻辑：构图数学、拼版几何、质检规则、打印编排 —— 这些是「代码」，不是「资产」，
  可以按行为复刻而无需拷贝实现。

所以 1:1 复刻在**能力上完全可行**，剩下的都是工程量与环境问题（见第六、七节）。

```
└────────────────────────────────────────────────────────────────────────┘
```

三条架构结论，直接决定复刻策略：

1. **渲染层就是标准 React + Vite 产物**，没有自研 UI 框架，组件边界清晰，可逐屏对齐。
2. **算力全在前端**（wasm/tflite），主进程只管「窗口、协议、打印、落盘」——
   所以复刻可以完全跑在浏览器里，打包成 Electron 只是补最后 5%。
3. **拼版与打印是「纯函数 + 位图」**：几何全部以 mm 为单位算出，出图时才乘 DPI。
   这是爱印能做到「预览 = 导出 = 打印」的根本原因，也是最该照抄的设计。

## 四、关键业务流程

### 4.1 证件照批量（导入 → 抠图 → 构图 → 导出）

```
选择文件/文件夹/拖入
   └─ 过滤（非图片跳过；HEIC 明确提示不支持；>16MP 走缩放路径）
      └─ 逐张 decode → 缩略图立即入列表（不阻塞后续）
         └─ 抠图队列（Worker 池，numThreads=min(4, cores-1)，SAB 失败降单线程）
            └─ alpha 回主线程 → 换底合成（输出分辨率上做，不是原图分辨率）
               └─ Face Landmarker 关键点 → 6 度量 → 按规格自动构图
                  └─ 人工微调（取景编辑器）→ 导出（JPG/PDF，多规格）
```

性能上最关键的一条：**合成在输出分辨率上做**。1 寸 295×413 相比 12MP 原图，像素量只有 1/95，
换底色从「秒级」降到「毫秒级」。这条在复刻版已复现（`docs/idphoto-batch-performance.md`）。

### 4.2 图片拼版（本次新复刻的核心）

```
导入 N 张图（记录 width/height；长图额外扫「逐行空白」标记）
   └─ 按 section 分组（一张图可携带自己的 layout 覆盖，从它起另起一组）
      └─ 每组：
         ├─ 常规模式：中位宽高比 → 统一单元格 → 逐张等比缩放 → 逐行取最高 → 行内居中
         └─ 排满模式：同一张图重复 → 列宽由「份数」或「指定宽度」反推 → 按行堆叠 → 满页换页
            └─ 合并页序列 → 统一编页码 → 质检（PPI/边距/长条）
               └─ 预览（2.2px/mm） 与 导出（300dpi）共用同一份几何
                  └─ PDF（整页位图写满纸）/ 打印（主进程静默出纸）
```

### 4.3 打印输出

- 两条通道：**系统打印面板**（用户在面板里选纸/份数，最稳）与**静默直出**（主进程把 PDF 栅格化后送印）。
- 拼版场景默认静默直出：`dpi=400`（证件照/证卡这种小纸，400 比 300 更保险）、`copies=1`。
- 纸张「跟排版走」而不是跟打印机默认走 —— 否则 A4 排的版打到 A5 上会被缩成一团。

## 五、拼版引擎逐条拆解（复刻的核心资产）

对应复刻文件：`src/lib/photoSheet.ts`（纯函数，961 行含注释），单测 `photoSheet.test.ts`（27 条）。

### 5.1 全部常量

| 常量 | 值 | 含义 |
|---|---|---|
| 页边距 | 10 mm | 固定，不给用户调（家用打印机普遍有 5~10mm 不可打印区） |
| 图注行高 | 6.8 mm | 有图注时每格额外占位 |
| 正文字号 | 4.2 mm | ≈12pt，按 mm 定义，任何 DPI 下比例一致 |
| 图注间隙 | 1.2 mm | 图片底边到文字 |
| 页码高度 | 7 mm | 开页码时从可用高度里扣 |
| 尺寸标注 | 5 mm | 排满模式「标注尺寸」额外占位 |
| 间距上限 | 10 mm | 单元格最多能撑到多大间距，超出被压回 |
| 行列范围 | 1~6 | 显式行列，非法值当没填 |
| 间距滑杆 | 0~420 mm | 允许夸张值，但会被上限压回 |
| 排满宽度 | 10~400 mm | 「每个的宽度」 |
| 份数上限 | 999 | |
| 宽高比钳制 | 0.3~2.3 | 中位数后再钳制，防超长图拖垮整页 |
| 长图阈值 | 2.5 倍 / 容差 1.15 | 高 ≥ 宽×2.5 才考虑切段 |

### 5.2 网格求解（`computeGrid`）

```
maxGapX = (可用宽 − 列数×10) / (列数−1)
gapX    = min(用户间距, maxGapX)          ← 关键：先算「还能塞多大间距」
cellW   = (可用宽 − gapX×(列−1)) / 列
cellH   = (可用高 − gapY×(行−1)) / 行
imageH  = cellH − 图注行高
```

如果直接 `cellW = (可用宽 − 用户间距×(列−1)) / 列`，用户把间距拉到 50mm 就会得到负宽度，
版面直接崩。爱印用「先算上限再取 min」避免了这个分支 —— 复刻版保留了同样顺序，
单测里有一条专门把间距设成 400mm，断言格子仍有 10mm 宽。

### 5.3 自动行列（`autoGrid`）

在「每页个数」的所有因数分解里挑**单图最大**的一种，且单边 ≤4：

```
6 张正方图 / A4：3×2 → 单图 60mm；2×3 → 单图 82.2mm  ⇒ 选 2×3
```

之所以限制 4×4，是因为不限制的话 50 张会被排成 1×50 的碎条（页数最少但完全不能用）。

### 5.4 长图自动分段（`splitLongParts`）

三步：

1. **逐行空白检测**：每行取中间像素做基准，统计差异 >14 的像素数；低于「宽度×0.4%」判为空白行。
2. **找切点**：目标块高 `chunk = 图宽 × 单元格比例 × 空白率`，在 `[0.55·chunk, chunk]` 的窗口里
   找最靠近窗口中点、且宽度 ≥ 图宽 2.5% 的空白区间；找不到就按窗口右端硬切。
3. **换算回源图坐标**：切点 / 空白率 = 源图 y，最后一段用图高收尾。

这样切出来的每一段都落在聊天气泡/文字行的间隙里，不会切断一行字。切完在页面上标「（1/3）」。

### 5.5 常规分页（`paginateNormal`）

```
aspect = clamp(中位(高/宽) ?? 1.4, 0.3, 2.3)
grid   = 显式行列 ? computeGrid : autoGrid(每页个数)
for 每张图: parts = splitLongParts(...)      // 一张长图可能变多段
for 每页:  逐段按自身比例在格子内等比缩放
           rowH[行] = max(该行图高 + 图注)
           总高 = ΣrowH + gapY×(行数−1)
           起始 y = 边距 + (居上/居中/居下)·剩余空间
           x = 单元格左 + (cellW − 图宽)/2      // 框内水平居中
```

**为什么不用「统一高度」**：统一高度会裁掉长图；统一宽度会让同页高矮差距夸张。
爱印的做法是「统一格子、图各自缩放、行高取最高」，既保比例又不裁图，代价是行内顶端对齐、
底部参差 —— 这是它一眼能认出来的观感来源。

### 5.6 排满模式（`paginateFill`）

```
若指定宽度 w：列 = ⌊(可用宽+gap)/(w+gap)⌋，行 = ⌊(可用高+gap)/(w·ratio+标注+gap)⌋
             放不下 → 缩到「一页一个」并置 tooLarge（界面提示换纸/换小）
否则按份数：在份数的因数分解里挑单图最大 → 再用剩余空间补满列/行
逐份：最后一行未满 → 同行追加；满列或换尺寸 → 新行；行底越界 → 新页
裁切线：竖线（首组贯通纸顶、末组贯通纸底），横线（每行上下边）
```

### 5.7 分组与页码

`section` 挂在某张图上 = 从这张起用这套覆盖设置，直到下一个带覆盖的图。每组独立分页，
但页码在合并后统一编号（`第 3 页 / 共 7 页`，而不是每组各算一套）。

### 5.8 打印质检（`checkSheets`）

| 规则 | 阈值 | 为什么 |
|---|---|---|
| 分辨率过低 | PPI < 120 | 手机截图缩到 3cm 宽再印，肉眼看就是糊的 |
| 贴边 | 距纸边 < 5mm | 多数打印机有不可打印区，贴边必被裁 |
| 长条截图 | 高/宽 ≥ 2.5 且印出宽 < 90mm | 长图塞进小格子后完全看不清，应开长图分段 |
| 缺字体 | 上报缺失字体 | 拼版用系统字体，PDF 类工具才需要嵌入 |

前三条来自 `page-checks-qADN07Uf.js`，复刻版原值照抄（`CHECK_LIMITS`）。

## 六、React 复刻方案

### 6.1 当前仓库的模块划分（已落地）

```
src/
├─ lib/
│  ├─ photoSheet.ts            拼版几何引擎（纯函数，零依赖，962 行）
│  ├─ photoSheetRender.ts      mm→px 渲染（预览 2.2px/mm / 导出 300dpi）
│  ├─ sheetPdf.ts              jsPDF 写入（整页位图写满纸，页数/尺寸可控）
│  ├─ specFraming.ts           证件照按规格构图（6 度量）
│  ├─ idphotoCompose.ts        合成编排（预览/导出共用一份）
│  ├─ matting*.ts              抠图池 + Worker（onnxruntime-web）
│  ├─ idphotoRetouch*.ts       匀肤（掩码 × blend）
│  ├─ cardLayout.ts            证件照规格表 / 排版页构建
│  └─ printers.ts              打印通道（静默直出 / 系统面板）
├─ tools/
│  ├─ ImageLayout.tsx          图片拼版工作台（左图栏 / 中预览 / 右设置）
│  ├─ IdPhoto*.tsx             证件照三栏工作台
│  ├─ CardLayout.tsx           证卡拼版
│  └─ BatchPrint.tsx           批量打印
└─ electron/                   窗口、IPC、打印、原子写盘
```

### 6.2 数据流（单向，不用全局 store）

```
UI 事件 ──▶ setLayout / setItems（唯一真源）
              │
              ├─ useMemo: sources = items.map(→ SheetSource)
              ├─ useMemo: result  = layoutSheets(sources, layout)   ← 纯函数，可单测
              ├─ useMemo: issues  = checkSheets(result, sources)
              └─ useEffect: renderSheetPage(canvas, page, {pxPerMm})
                           （导出时同函数、只换 pxPerMm）
```

三条硬约束：

1. **几何只在 `photoSheet.ts` 里算**。组件不做任何 mm 级运算，否则预览与导出必然漂移。
2. **渲染只有一份**。预览与导出调用同一个 `renderSheetPage`，差别只有 `pxPerMm`
   （2.2 vs 11.81）。这是「所见即所印」的唯一可靠实现方式。
3. **分组 = 数据，不是状态分支**。`section` 挂在 source 上，引擎按它切组，
   组件只负责「当前选中图属于哪一组 → 读写哪一份 layout」。

### 6.3 关键实现细节（都是踩过的坑）

| 坑 | 现象 | 处理 |
|---|---|---|
| 高度写死 `calc(100vh - N)` | 底部常驻空白，换窗口就露馅 | 父级 `.main` 是 flex 子项，子元素 `height:100%` 即可 |
| 画布 `max-width/max-height` 同时设 | canvas 两轴被独立钳制 → 纵横比失真 | 只约束高度或用容器 `object-fit` 思路，保持宽高由属性决定 |
| PDF 逐格矢量重建 | 与预览有毫米级偏差，裁切线位置对不上 | 整页 300dpi 位图写满纸；几何只信 mm |
| 预览用 `transform: scale` | 命中测试/遮挡判定不可靠 | 用 CSS `zoom` 或容器尺寸，交互元素不用绝对定位+transform |
| 图注测宽用 `measureText` | 与绘制时不符（字体未加载） | 按 em 权重估算（CJK 1、西文 0.6），与爱印一致且稳定 |
| 长图切点用零散空白 | 切断文字行 | 只在「连续空白且足够宽」的区间切，窗口偏后 |

## 七、可行性与风险（代码层面）

### 7.1 可行性结论

| 能力 | 结论 | 依据 |
|---|---|---|
| 拼版几何 | **完全可行（已实现）** | 9.4KB 纯函数，输入输出明确，27 条单测钉住数值 |
| 证件照抠图 | **可行** | MODNet/ISNet 开源权重 + onnxruntime-web，已跑通 50 张 45s |
| 按规格构图 | **可行** | 纯几何 + Face Landmarker（官方开源模型） |
| 匀肤/美颜 | **有条件可行** | 爱印 retouch-v1 是私有权重；替代方案是开源美颜或自训，效果需调 |
| 打印静默直出 | **可行（平台相关）** | Electron 主进程 + 系统打印；Windows 稳，macOS/Linux 需分别验证 |
| 批量制卡（OCR/角点） | **可行但成本高** | opencv.js + OCR 模型，属独立工具链 |
| 加密资产读取 | **不需要** | 复刻不触碰任何加密产物 |

### 7.2 风险清单

**R1 排版算法复杂度 —— 低**

- 复杂度是 O(张数) 的线性编排，没有回溯/装箱搜索。50 张 A4 实测 `layoutSheets` < 5ms。
- 唯一非线性的是长图切分，但它也是单次线性扫描 + 局部窗口。
- 风险点不在算力，而在**规则组合爆炸**（分组 × 排满 × 长图 × 图注 × 页码）。
  应对：把规则拆成互斥的两条分页路径（常规/排满），其余全是参数；每条规则配单测，
  而不是让分支互相嵌套。

**R2 图片处理性能 —— 中**

- 内存：300dpi A4 位图 2480×3508 ≈ 35MB/页。10 页同时渲染会到 350MB。
  应对：导出时**逐页渲染、逐页写入、写完即释放**（当前实现一次拿全页数组，页数多时要改流式）。
- 解码：50 张 12MP JPEG 全解码 ≈ 1.2GB 常驻。应对：列表只留缩略图，导出按需解码；
  爱印对 >16MP 走缩放路径，同理。
- 长图空白扫描：400px 宽扫 12000px 高 ≈ 1.9M 像素，单张 ~15ms；已限制只扫 ratio>2.5 的图。

**R3 打印精度适配 —— 中高（最容易「看着对、印出来错」）**

- 单位链必须是 mm 一条线到底：排版 mm → PDF mm → 打印机实际纸。任何一环转到 px 再转回来，
  都会引入 ±0.3mm 误差，裁切线就会偏。
- 打印机不可打印区（通常 3~5mm）与固定 10mm 页边距是两件事：前者是硬件限制，
  后者是版式选择。**不要用页边距去「兜」硬件限制**，否则换台打印机会突然贴边。
- 缩放必须 100%：Windows 打印对话框默认「适应页面」，A4→A4 也可能被缩到 96%。
  静默直出时显式设 `scale=1`、`paperSize` 跟随排版纸张。
- 建议：导出前让用户在 PDF 里确认「1 元硬币/尺子」参考线，或直接量第一条裁切线到纸边距离。

**R4 依赖与环境兼容性 —— 中**

- `onnxruntime-web` 的 wasm 多线程需要 `SharedArrayBuffer` → 需要 COOP/COEP 响应头。
  Electron `file://`/自定义协议下要显式设置；浏览器部署时 Nginx 也要配。
- MediaPipe Tasks-Vision 依赖 wasm 与模型包，首次加载 ~4MB；离线包要一起打包。
- 打印与落盘是 **Electron 专有**：纯浏览器只能走 `window.print()` + 下载，功能会缺一截。
- Node/Electron 版本升级会牵动原生依赖（sharp/canvas 类），建议锁定大版本。

**R5 法务与合规 —— 低（但有边界）**

- 复刻的是**行为与规则**（几何、阈值、交互），不复制加密资产、不内置爱印模型权重、
  不使用其商标与图标。模型全部替换为 Apache-2.0/开源权重。
- 界面文案与版式可以对齐观感，但不应逐字复制其品牌语；建议保留自己的产品名与图标。

**R6 观感细节 —— 中**

- 「一眼像不像」取决于：字号阶梯、圆角、间距节奏、灰阶层次，而不是功能。
  这类差异无法靠读代码得到，只能截图逐屏比对。本项目已建立两套界面门禁
  （`verify:preview` 37 项 / `verify:sheet` 24 项）+ 截图人工复核。

## 八、关键难点与应对

| 难点 | 为什么难 | 应对 |
|---|---|---|
| 预览与导出不一致 | 两套代码路径必然漂移 | 几何/渲染各只保留一份实现，差异只有 `pxPerMm` |
| 长图不切断文字 | 需要像素级空白检测 + 窗口搜索 | 逐行空白 + 连续区间 + 偏后窗口；阈值可调 |
| 排满时「放不下」 | 用户输入任意宽度 | 明确降级到「一页一个」+ tooLarge 提示，而不是悄悄裁掉 |
| 分组后页码 | 每组独立分页但要统一编号 | 先合并页序列，再统一写 footer |
| 大批量内存 | 300dpi 位图很大 | 逐页流式写出；导出前限制页数并提示 |
| 打印偏移 | 硬件不可打印区 + 缩放 | 10mm 版心 + 强制 100% + 静默直出指定纸张 |
| 字体 | 不同系统字体不同，图注可能超宽 | 用 em 权重估算宽度做中段省略；不依赖 measureText |
