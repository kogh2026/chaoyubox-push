# V4「MODNet + 边缘精修」— 边缘精修模块设计与实测

> 2026-11-03。目标：消除换底后发丝/轮廓外沿残留的原底色晕边，同时保留发丝的透明白边与细节层次。
> 结论前置，详见下文。**所有数字来自本机实测**（51 张学员寸照 + 12 张浏览器真机性能测量）。

## 0. 结论前置

| 问题 | 判定 | 一句话理由 |
|---|---|---|
| 残留底色的成因是什么？ | **颜色溢出（color bleeding）** | 半透明像素的 RGB 天然是「前景×alpha + 原底色×(1−alpha)」的混合色，抠图只给 alpha，RGB 没解混 |
| 主因在哪个区？ | **半透明带**（0<alpha<250） | 实测该带内 23%~60% 的像素 RGB 仍接近原底色；不透明区几乎为 0 |
| 精修插在哪？ | **Worker 内、抠图推理后、合成 PNG 前** | 只有这一时刻原始 RGBA（未被 premultiply）与 alpha 都在手上，能估到底色，也是换底固化残留前的最后机会 |
| 效果如何？ | ✅ **有效** | 晕边 0.51% → **0.24%**（−53%）；残留 12.53% → **9.96%**（−20%）；发丝细节保持 **1.156**（>1，更清晰而非丢失） |
| 性能开销 | ✅ **可忽略** | 真机实测 **21ms/张**，占抠图推理（1695ms/张）的 **1.2%** |
| alpha 会被改吗？ | ✅ **不会** | 真机测量 alpha 改动像素数 **= 0**。发丝的半透明层次、形状、数量全部保留 |
| 真实 Worker 端到端 | ✅ **有效** | 真实 Worker + 真实 MODNet 模型跑 10 张：边缘残留 **42.84% → 29.17%（降 32%）**，蓝底样本降 37%~63% |

## 1. 成因诊断（这是整个方案的地基）

### 1.1 先排除两个常见猜测

| 猜测 | 验证方式 | 结论 |
|---|---|---|
| 「抗锯齿导致边缘发虚」 | 看 alpha 分布直方图 | ❌ 不是主因：alpha 呈**强二值化**（alpha=0 占 38%、alpha≥253 占 59%，中间过渡带仅约 2.4%），几乎没有可"发虚"的半透明层 |
| 「模型把背景误判成前景（硬残留）」 | 统计 alpha≥250 且 RGB≈原底色的像素 | ❌ 不是主因：多数样本该值为 **0.00%**，仅白底图上的白衣属正常误判 |
| ✅ **「颜色溢出」** | 统计半透明带的 RGB 构成 | **是主因**：半透明带（0<alpha<250）内 **23%~60%** 的像素 RGB 仍接近原底色 |

### 1.2 物理机制

照片里「发丝」这类半透明像素本身就是**混合色**：

```
观测值 C = a · F + (1 − a) · B
  C = 原图像素（混合色）   a = alpha 蒙版
  F = 纯前景色（发丝本色）  B = 原底色（蓝/红/白）
```

这是光栅化/衍射的必然结果，**不是模型的错**。抠图模型只输出 alpha 蒙版，
前景像素的 RGB 仍是原图的混合色 → 直接贴到新底色，混合色里的原底色分量就在新底上显形。

**分层数据**（样本 430204199403147013，蓝底 RGB(115,175,217)，正确底色为 (14,140,200)）：

| alpha 区间 | 像素数 | RGB 接近原底色占比 | 换白底后亮度均值 |
|---|---|---|---|
| 16–64 | 6767 | 0.0% | 101.6 |
| 64–128 | 4856 | **7.1%** | 96.4 |
| 128–240 | 11513 | **3.9%** | 92.4 |

→ 残留集中在 **alpha 64–192** 的过渡区，正是发丝所在。

### 1.3 ⚠️ 一个关键的测量陷阱（踩过，记下来）

**底色估计不能用「四角采样」**。证件照的四角常常落在人像（肩膀、浅色衣服）上：

| 样本 | 四角法给出的底色 | 真实底色 | 四角法错在哪 |
|---|---|---|---|
| 红底照 | (234,126,133) | **(239,22,30)** | 四角落在肤色上，把肤色当成了底色 |
| 蓝底照 | (115,175,217) | **(14,140,200)** | 四角有渐变/阴影 |
| 浅灰照 | (155,156,161) | **(255,255,255)** | 主体偏暖 |

**正确做法**：用 **alpha≈0 区域的中位数** —— 那是模型判定的「确定背景」，最可靠。
（验证过：产品 MODNet 输出的透明 PNG 里，alpha=0 区域 RGB 精确等于原底色，如蓝底照 `(14,140,200)`。）

> 用错底色会把前景推向错误颜色，越修越糟 —— 这是第一版实验改善只有 11% 的原因。

## 2. 边缘精修的方案

### 2.1 核心算法：颜色解混（unmix / color decontamination）

反解出纯前景色再写回：

```
F = (C − (1 − a) · B) / a
```

**只改 RGB，绝不动 alpha** → 发丝的半透明层次、数量、形状全部保留，
改的只是「半透明像素里混进去的那部分原底色」。

### 2.2 三步流水线（`src/lib/edgeRefine.ts`）

```
① 解混 + 色域钳制
   F = (C − (1−a)·B) / a
   钳制：以 C 为中心、半径 max(24, |C−B|·2.5)
   —— 纯前景色 F 天然超出混合色 C 的范围（C 是 F 与 B 的加权平均），
      所以不能把 F 钳在 [min(C,B), max(C,B)] 内；那样反而会把解混结果掐死

② 空间平滑（仅在边缘带内部 3×3 盒滤波）
   —— 邻居若不在边缘带（全透明/不透明前景）不参与平均，
      否则孤立的发丝像素会被全透明邻居"稀释"成原色（第一版就踩了这个坑）

③ 置信度加权写回
   w = clamp(strength · (1 − (1−a)^(1/kappa)), 0.35, 1)
   —— 低 alpha 修得更狠（发丝区最需要），但保留下限 0.35 防止噪声放大
```

### 2.3 插入位置与作用范围

```
原图 ──► 抠图(MODNet) ──► 透明 PNG ──► ★边缘精修★ ──► 缩放 ──► 换底合成 ──► 成品
                              │              │
                              │              └─ 只处理 0<alpha<250 的像素
                              └─ alpha≈0 区域保留原底色像素 → 估 B 的唯一来源
```

**为什么必须在缩放前**：缩放后 alpha≈0 区域已被插值污染，估不出原底色。
**为什么必须在换底前**：换底是「底色×(1−a) + 前景×a」，一旦合成，残留被固化成色斑，再也分不出来源。

**作用范围**：
| 区域 | 是否处理 | 原因 |
|---|---|---|
| alpha = 0（全透明） | ❌ | 没有颜色可用；且这里的 RGB 正是估底色的样本，不能动 |
| 0 < alpha < 250（边缘/发丝） | ✅ | 唯一有残留可修的区域 |
| alpha ≥ 250（不透明前景） | ❌ | 本来就没有残留可修（实测该区近底色占比几乎为 0） |

## 3. 小样本测试方案

### 3.1 样本

- **素材**：`D:/50/学员寸照/` 1741 张中随机抽 25 张（seed=20261103，可复现）
- **覆盖度**：底色 蓝 11 / 浅杂 8 / 白 4 / 红 2；尺寸 198×297 ~ 1340×1799（5 档）
- **发丝难例**：用 alpha 边缘密度 + 上半部分（头发区）自动定位放大窗口，聚焦发丝

### 3.2 指标定义

| 指标 | 定义 | 方向 |
|---|---|---|
| **晕边率 haze** | 边缘带内「仍接近原底色 **且** 离目标底色也远」的像素占比 —— 精确命中"挂着原底色"的元凶 | ↓ |
| **残留率 residue** | 边缘带内接近原底色的像素占比 | ↓ |
| **平均色偏** | 边缘带内与原底色的平均 \|ΔRGB\| | ↓ |
| **细节保持 detailRatio** | 边缘带 R 通道梯度幅值之比（精修后/精修前），>1 说明层次更清晰，<1 说明被抹平 | 接近或 >1 |
| **alpha 改动数** | 精修前后 alpha 不同的像素数（真机测量） | **必须 = 0** |

### 3.3 结果（8 张，目标底色蓝 #438EDB）

| 策略 | 晕边 | 残留 | 平均色偏 | 细节保持 |
|---|---|---|---|---|
| none（精修前） | 0.51% | 12.53% | 274.2 | 1.000 |
| naive（旧 defringe 等价） | 0.31% | 11.78% | 282.8 | **0.959** ← 细节被抹平 |
| **unmix（本次方案）** | **0.24%** | **9.96%** | 290.8 | **1.156** ← 细节更清晰 |

单张明细（晕边率）：

| 样本 | none | naive | unmix |
|---|---|---|---|
| 430204199403147013 | 0.35% | 0.32% | **0.00%** |
| 430302198211112308 | 0.00% | 0.00% | 0.00% |
| 430726199801273416 | 1.05% | 0.64% | **0.33%** |
| 433127199505285814 | 2.38% | 1.25% | **1.34%** |

### 3.4 为什么不用旧的 defringe

旧 `defringe` 把边缘 RGB **整体替换**为最近不透光邻居的纯色 → 把发丝自身的色调与半透明渐变一起抹平。
实测：细节保持仅 **0.959**（低于 1 = 细节损失），残留反而**升高**（11.78% vs 12.53% 基线中的 naive 项）。

→ 新方案启用时**必须关掉旧 defringe**（两者目标相反、互相抵消）。已在 `IdPhoto.tsx` 接线。

## 8. 架构关键点：精修必须在 Worker 内做（踩过的最大坑）

### 8.1 现象

第一版实现把精修放在**主线程**：抠图输出的透明 PNG → `createImageBitmap` → canvas → `getImageData` → 精修。
真机跑 25 张，**底色估计全部是 `(0,0,0)`**，精修完全无效（解混用 B=(0,0,0) 会把前景推向错误颜色）。

### 8.2 根因

**canvas 内部是 premultiplied 存储**。PNG 里 alpha=0 的像素，RGB 在解码后仍是原值，
但一旦进 canvas，`getImageData` 返回的 RGB 已被 premultiply 处理 —— alpha=0 的像素 RGB 变成 0。

而那片区域恰恰是**估计原底色 B 的唯一可靠来源**（alpha≈0 = 模型判定的确定背景）。

### 8.3 解决方案

把精修搬到 **Worker 内**（`matting.worker.ts` 的 MODNet 路径）：
- Worker 里原始 RGBA（`putImageData` 写入的，未 premultiply）与 alpha 蒙版**都在手上**
- 合成 PNG **之前**就地改 RGB → 底色估计正确（实测蓝底照估出 `(14,140,200)`，与真实底色一致）
- 顺带好处：精修在 Worker 线程跑，**不阻塞主线程 UI**

### 8.4 单一实现，避免两份代码漂移

核心算法只有一份：`src/lib/edgeRefine.ts` 的 `refineEdgePixels(rgba, alpha, w, h, opt)`。
- Worker（`matting.worker.ts`）import 它 —— alpha 用模型输出的 Float32Array
- 单测直接调它 —— alpha 从 RGBA 第 4 通道读
- 另有 `refineEdge()` 便捷包装（从 RGBA 读 alpha），供主线程侧调用

> `refineEdgePixels` 把 alpha 数组**外部传入**而非从 RGBA 里读，正是为了让两种来源共用同一份算法。

### 8.5 ISNet 路径不支持精修

@imgly 的输出是「已合成 alpha 的 PNG」，alpha 已被 premultiply 进像素，拿不到未混合的原始 RGB
→ 无法解混。故 ISNet 路径不做精修（界面已不再暴露该档，`modnet-refine` 才是推荐路径）。
