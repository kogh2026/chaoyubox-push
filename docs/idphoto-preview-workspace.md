# 证件照工作台：导入 → 自动抠图 → 逐张大图预览（复刻爱印交互）

> 参照对象：爱印工具箱 v0.6.0「证件照批量处理」页（截图见 `docs/ui-reference/`）。
> 实现在 `src/tools/IdPhoto.tsx` + `IdPhotoLeft/Center/Right.tsx`，样式在 `src/index.css`（`.idp-*`）。
> 门禁：`npm run verify:preview`（`tools/idphoto_preview_smoke.py`，37 项）。

## 一、整体布局：三栏 + 一条底栏

```
┌──────────────┬───────────────────────────────┬──────────────┐
│ 左栏 272px   │ 中栏 1fr（≥320px）            │ 右栏 286px   │
│ 导入 / 列表  │ 当前照片的大图 + 工具条       │ 参数面板     │
├──────────────┴───────────────────────────────┴──────────────┤
│ 底栏：本批概览 │ 尺寸标注 · 人像定位线 │ 排版导 PDF / 打印 / 开始导出 │
└─────────────────────────────────────────────────────────────┘
```

`.idp` 用 CSS Grid 定宽三列（`272px minmax(320px,1fr) 286px`），行高 `1fr auto`，
**三栏各自滚动**，页面本身不滚。
分数列给中栏：左栏是固定宽度的列表、右栏是固定宽度的表单，只有大图需要"剩下多少用多少"。

### 高度：`height: 100%`，不要写死减多少

`.main` 是 `.app`（`height: calc(100vh / var(--ui-zoom))`）的 flex 子项，高度已经确定，
所以工作台只需 `height: 100%` —— 它自己就等于「整屏减掉 `.main` 的上下 padding」。

历史坑：原先写的是 `calc(100vh / var(--ui-zoom) - 120px)`，等于「按顶部工具栏 120px 预留」，
而实际只有 `.main` 的 24px 上下 padding。于是**任何窗口尺寸下，底栏下面都会拖出一条 70~90px 的空白**，
它和内容无关、也不随窗口变化，纯粹是猜出来的数字。现在改 100%，底部间隙恒等于 `.main` 的 padding（24px），
`verify:preview` 里用「窗口底部 − 工作台底部 ≤ 32px」+ 换一个窗口尺寸再量一遍来钉住这件事。

回收的这 70~90px 按「谁最需要空间」重新分配（1200×780 实测）：

| 去向 | 变化 | 理由 |
|---|---|---|
| 中栏大图 | 画布 630 → 690，照片 460 → 520（+13%） | 这是整页唯一「越大越好」的区域，调参看的就是它 |
| 左栏列表 | 可视行数 +1 | 一列列表在 50 张批次里越能多看一行越省滚动 |
| 右栏参数 | 可视内容 +70px（仍高于栏高，需滚动） | 六段式表单本来就长，多一点就少滚一点 |

横向也顺手收了一下：左栏 288 → 272（行内只有 46px 缩略图 + 三行文字，288 富余），
省下的 16px 让给中栏。左右两栏现在顶/底严格对齐（`verify:preview` 里有断言），
不再出现「底栏比三栏短一截、三栏又比底栏长一截」的错位感。

## 二、各区域职责

### 左栏 `IdPhotoLeft` —— 批次与"看哪张"

| 区域 | 职责 |
|---|---|
| 导入照片 / 导入文件夹 | 两枚通栏按钮（爱印式上下排布），隐藏 `<input type=file>`（`webkitdirectory` 支持整目录） |
| 全选 · 已选 N/M · 清空 | **导出范围**的批量操作；与"当前查看"无关 |
| 照片列表（一列） | 每行 = 勾选圆钩 + 成品缩略图 + `照片 N` + 原文件名 + 状态行；**整块列表是投放区**，拖照片进来直接追加 |
| 列表末尾提示 | `共 N 张 · 继续拖入照片或文件夹可追加`（照片少时沉到列表底部，把余下留白收口成一行说明） |
| 演示照片 | 内置两张真实人像，一键走完整链路（无照片时也能试） |

一行里的三层状态，各自独立：

- **圆钩**（`.idp-check`）= 是否加入导出集合（`checked`）。点击 `stopPropagation`，不会切换预览。
- **行体点击** = 切换中栏主预览（`setActiveId`），行体加 `.act` 高亮。
- **状态行** = `抠图中…` / `合成中` / `已处理`（绿）/ `失败`（红），外加第一条异常提示（橙，如"背景不纯"）。
  缩略图右上角只留一个 8px 绿点（已处理），状态文字不再挤在图上。

### 中栏 `IdPhotoCenter` —— 当前照片的放大预览

| 元素 | 说明 |
|---|---|
| 证件照 / 排版照 页签 | 两套产出：单张成品 与 整版排版 |
| 原图 ⇄ 成品 | 右上角常驻切换，用于对比抠图/换底效果（原图态左上角有「原图」角标） |
| 大图 | 只有**一张**，纵横比跟随当前规格（一寸 = 25/35），高度撑满可用空间 |
| 尺寸标尺 | 照片正下方一行 `1寸 · 25 × 35 mm · 295 × 413 px`（规格名 + 毫米 + 像素，不重复写两次尺寸），随缩放一起放大（受底栏「尺寸标注」控制，默认开） |
| 悬浮翻页 ‹ › | 画布两侧，循环切换；只有 1 张时隐藏 |
| 页码胶囊 | 画布右下角 `3 / 52` |
| 工具条 | `− 100% + 适应` ｜ `⛶ 取景微调` · `↓ 保存这张` |

未出片时不再是空白：画布显示**原图 + 进度文案**（占位元素刻意不带 `.idp-photo-card`，
那道类名是"成品已就绪"的信号，被多个门禁当作等待条件）。

### 右栏 `IdPhotoRight` —— 参数面板

五段式（照片规格 / 人像构图 / 规格构图核查 / 背景与抠图 / 人像优化 / 多张排版），
顶部有「设置会自动保留」与两段式确认的「恢复默认」。参数改动**不需要按任何按钮**：
`retouch` / `advOpts` / `placements` 一变，合成 effect 立刻重算，中栏大图与左栏缩略图一起更新。

### 底栏（三段）

| 段 | 内容 | 对应心智 |
|---|---|---|
| 左 `.idp-bottom-l` | `将导出 N 张 · 规格 · JPG`（多规格时 `N 规格 × M 张 = K 份`）、当前照片与像素、失败计数（有才出现） | 在看什么、会导出什么 |
| 中 `.idp-bottom-m` | 尺寸标注 / 人像定位线 两个显示开关 | 画布怎么显示 |
| 右 `.idp-bottom-r` | 排版导 PDF / 打印 / 开始导出 | 要做什么 |

中段吃掉弹性空白、两侧各一条竖线成组；窗口变窄时整条 `flex-wrap` 换行，不会挤成一团。
失败计数（`N 张失败`，红）是这轮补的：失败的图不参与导出，但以前只在左栏那一行上有红字，
批量 50 张时几乎不可能发现。

## 三、交互联动关系（数据流）

```
导入 File
   └─ items[]（每张一个稳定 id + objectURL）
        ├─ 抠图 effect ─→ matteCache(id→PNG)  ── 每完成一张 mattesVer+1（节流 300ms）
        └─ 合成 effect ─→ results[](id→JPEG+URL) ──┬─→ 左栏缩略图（有就显示成品）
                                                   ├─→ 中栏大图（当前 activeId 那条）
                                                   └─→ 排版 canvas（只取勾选的）
activeId ─────────────→ 中栏大图 + 左栏 .act 高亮（只影响"看哪张"，不触发重合成）
checked  ─────────────→ 导出范围 / 排版内容 / 底栏与右栏份数（不影响预览）
右栏参数 ─────────────→ retouch/adv/placements → 合成 effect → 全部成品重算
```

三条关键设计：

1. **"看哪张"与"导出哪些"分离**（`activeId` vs `checked`）。
   合并成一个状态会立刻打架：用户在 50 张里点第 30 张只想看效果，不该改变导出范围；
   反之取消勾选也不该把大图换掉。

2. **当前照片优先出片**。合成分两段：先单独合成 `activeId` 那张并提交（大图立刻更新），
   再合成其余（人物层缓存命中，只重新合层）。拖一次滑杆，主预览先动，剩下的在几十毫秒内补齐；
   否则 50 张排在前面的照片会让人以为"滑杆没反应"。

3. **抠图逐张出片，合成只补缺的**。抠图每完成一张就 `mattesVer+1`（300ms 节流），
   左栏那一行当帧翻成成品；合成侧用「参数指纹」判断：指纹没变就只合成"还没有成品"的 id，
   指纹变了才整批重算。没有这一步，逐张通知会退化成 O(n²)（50 张 → 每张都重算全部）。

## 四、与改造前的差异（为什么不是"网格"了）

改造前中栏把所有成品铺成缩略图网格（每张一卡 120px），左栏也是 220px 的网格卡。
批量 50 张时看不清任何细节，也无法"点开某张调参看效果"，这是与爱印最大的交互差异。
现在：左栏一列、中栏一张、参数改动实时回到这一张 —— 调参的反馈闭环才成立。

## 五、已知边界

- 缩略图与排版都用同一份 300DPI 成品，换规格会整批重算（人物层缓存兜住大部分开销）。
- 中栏缩放是 `zoom`（参与布局，可滚动），倍数不随切换照片重置 —— 逐张对比发丝边缘时更顺手。
- 悬浮翻页按钮是**附加**入口；主要切换方式仍是点左栏行体（与爱印一致）。
- 分辨率门禁覆盖：`verify:preview`（本页交互）、`verify:framing`（取景编辑器）、
  `verify:export`（导出字节特征）、`verify:persist`（设置落盘）、`preview_multisize`（右栏多规格）。
