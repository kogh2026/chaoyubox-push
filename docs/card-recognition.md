# 证件识别复刻：爱印的方案拆解与「超誉」的实现

> 背景：两边同样是「导入一张手机翻拍的身份证」，爱印给出的是一条**摆正、裁净、比例正确**的卡面，
> 超誉给出的却是把桌面裁进来、或者干脆锁到某行文字上的歪斜结果。差别的根源不在 UI，而在
> **检测层**——旧实现只做「行/列梯度剖面」，本质只能找**轴对齐**的四边形；一旦卡片有旋转、
> 透视，剖面峰值就落到文字行上，于是越裁越错。

本文记录三件事：爱印到底怎么做的、我们把哪一段换成了什么、以及还差什么。

---

## 1. 爱印的识别链路：两层定位 + 一道验收

源码位置（解密后的明文，`aiyin_decrypted_assets/`）：

| 文件 | 职责 |
|---|---|
| `vendor/multi-card-detect-worker.js` | 第 ① 层：OpenCV 轮廓粗定位（可一次找出多张卡） |
| `vendor/id2pdf-card-correction-worker.js` | 第 ② 层：ONNX 角点模型精定位 + 透视抠图 + 姿态摆正 + 循环抠除 |
| `vendor/id2pdf-ocr-worker.js` | 文字识别（判证件类型、判方向 turns） |
| `assets/desktop-tool-shell-Df-jYaXT.js` | 调度层：预热 worker、验收（纸白/字迹）、失败回退、多卡拆分判据 |
| `aiyin_models_decrypted/11680454a03dcfea.onnx` | 第 ② 层用的 768×768 角点回归模型（fp16，13MB） |

### ① 轮廓粗定位（`multi-card-detect-worker.js`）

```
缩放(长边 1200) → 灰度 → GaussianBlur(5) → 自动阈值 Canny → dilate(3×3, 2 次)
→ findContours(RETR_EXTERNAL) → 面积过滤 → approxPolyDP(0.02·周长)
→ 4 点且凸？用四点 : 退 minAreaRect
→ 长宽比过滤 → 打分 → NMS → 包住关系去重
```

关键常量（`V`）：

| 参数 | 值 | 含义 |
|---|---|---|
| `workingLongEdge` | 1000 | 工作分辨率长边（复刻时从 1200 降到 1000：满幅卡 + 盒式模糊下，1000 长边已足够，且单张省 ~15ms） |
| `minAreaFrac` / `maxAreaFrac` | 0.015 / 0.7 | 候选面积占比区间 |
| `approxEpsFrac` | 0.02 | DP 简化精度 = 0.02×周长 |
| `aspectMin` / `aspectMax` | 1.2 / 2.0 | 长宽比区间 |
| `blurKsize` / `dilateIter` | 5 / 2 | 模糊核、膨胀次数 |
| `nmsIoU` / `maxCards` / `minConfidence` | 0.3 / 12 / 0.35 | 去重与上限 |
| `autoCanny` | low = max(18, 0.5·m)，high = max(2.2·low, 1.2·m) | m 取灰度中位数 |

置信度是三项加权，**不依赖任何模型**：

```
conf = 0.4 · (approx4 ? 1 : 0.55)      // 四点近似比外接矩形可信
     + 0.35 · aspectScore(ratio)        // 与 85.6/54、88/60、143/105 的相对误差，1-2.5·err
     + 0.25 · extent                    // 轮廓面积 / 四边形面积
```

多卡判据（`J()`）——这是它能「一张 A4 上 4 张证」的原因：

- 至少 2 个 `approx4` 且 `conf ≥ 0.62`；
- 两两 IoU ≤ 0.12 且中心距 ≥ 0.14×短边（`ue()`）；
- 第二大卡面积 ≥ 第一大的 28%，否则判为「同一张卡被切成两半」；
- 外层还套了 `W()`/`ce()`：被更大框完全包住、或被 ≥2 个更大框包住的候选一律剔除（卡面文字框、防伪块）。

### ② 角点精定位（`id2pdf-card-correction-worker.js`）

粗定位的四点只能到「像素级、且被膨胀外扩几像素」。爱印在这里换成模型：

```
ImageData → 768×768 采样（S=[.408,.447,.47] 均值归一化）→ 3×768×768 张量
→ ORT(wasm) 一次前向 → 输出 scores / quads(4×2) / angle / ftype
→ 反归一化回原图坐标 → 按 score 排序（分层阈值 .3/.1/.03 + 面积比）
→ 用「点在四边形内」做包含式 NMS（ut()）→ 取最优
→ 用 angle 找 upright 角点 → 单应重采样裁出卡面（四边形外补白）
→ 把已裁走的多边形在源图上涂白 → 再跑一次 → 抠下一张（maxPages 循环）
```

`angle` 就是**四分之一圈数**（0..3），解决「卡横着/倒着拍」的问题；
`ftype` 是卡的子类型；`score` 是模型置信。

### ③ 抠完还要验收

调度层（`desktop-tool-shell`）在出图前再算两个量：

- `paperFraction`：卡面内部「接近纸色」的像素占比（对照纸色与阈值，非固定 183）；
- `inkFraction`：深色像素占比（证件必有文字/头像）。

判据 `paperFraction ≥ 0.97`，或 `≥ 0.80 且 inkFraction ≥ 0.003`（样本 ≥12）；
另加 `areaFrac ≥ 0.4`、`aspect ∈ [1.25, 2.15]`、`conf ≥ 0.55` 才算「这张卡可用」（`e4()`）。
不达标就不自动校正，回退原图让用户手动框——**宁可不动，也不给错图**。

## 2. 可复用的设计思路（不止于证件）

1. **两级定位**：便宜的传统 CV 负责「有没有、几张、大致在哪」，贵的模型只负责「精确四角」。
   80% 的图上第一级就能定案，模型调用是可省的。
2. **形态学 + 多边形简化**而不是「拟合直线」：先 dilate 把断续边缘连成环，再 DP 压到 4 点，
   对噪声远比 Hough 稳。
3. **评分而非阈值**：置信度是「方法可信度 + 形状先验 + 紧致度」的加权和，单一阈值判死会让
   侧面光、阴影的图全军覆没。
4. **包含关系去重**：卡片内部的文字框、头像框天然是「被更大框包住的小框」，用「被 ≥2 个更大框
   包住就删」比调 IoU 阈值稳得多。
5. **出图后验收**：用「纸色占比 + 字迹占比」验证裁出来的东西是不是一张证件。
   这一条直接决定「错图率」——我们的旧实现正是缺了这道闸。
6. **失败可回退**：任何一步不达标 → 不自动处理，保留原图 + 标「需检查」，交人工兜底。

## 3. 「超誉」这边改了什么

### 3.1 旧实现的问题

`src/lib/cardDetect.ts` 原先是「行/列梯度能量剖面」：找出「整列都是强梯度」的 x 与「整行都是强梯度」的 y，
得到一个**轴对齐矩形**。它天生做不了三件事：

- 卡片旋转（哪怕 3°）→ 四条边不再落在同一列/行上，峰值塌陷；
- 透视（俯拍）→ 上下边不等宽；
- 卡片占满画幅 → 中位数落在卡面白底上，Canny 阈值被抬到 280+，边缘直接丢。

于是「找不到就退回整图」，或者「锁到一行文字上」——就是截图里那张被放大到只剩笔画的卡。

### 3.2 新实现（纯 TS，不引 wasm / 不引模型）

| 模块 | 内容 |
|---|---|
| `src/lib/cvImage.ts` | 灰度、盒式模糊（两次≈高斯）、Sobel(L1)、自动阈值 Canny、分离式膨胀、直方图均衡 |
| `src/lib/cvContour.ts` | 8 邻域连通域（含像素索引表）、边界点、凸包、闭合 DP 简化、最小外接旋转矩形 |
| `src/lib/cvGeometry.ts` | 角点排序、面积/边长/长宽比、包围盒 IoU、包含率、单应求解与应用、**像素空间定向** |
| `src/lib/cardDetect.ts` | 管线编排、候选评分、NMS/嵌套去重、多卡判定、边缘精修、纸白/字迹验收、透视重采样 |

与爱印第 ① 层逐项对齐：工作分辨率、面积区间、DP 精度、长宽比区间、膨胀次数、置信度公式、
NMS 阈值、多卡判据的 0.62/0.12/0.14/0.28 全部同值。**两处有意偏离**，都写在代码注释里：

- **Canny 阈值的统计量从「中位数」改成 p25**（原图那一遍），并把直方图均衡那一遍保留用中位数。
  原因就是「满屏证件」场景：中位数会落在卡面白底上。改成 p25 更接近背景亮度，满幅卡也能过。
- **`maxAreaFrac` 从 0.7 放宽到 0.96**：0.7 是「多卡翻拍」的假设；单卡拍满画幅是常态。
  多卡拆分那条路径仍按 0.7 收口。

第 ② 层（模型）换成了**梯度边缘精修**，效果等价而不需要权重文件：

```
对四条边各取 12~48 个采样点 → 沿法向 ±2%·短边 搜索梯度峰
→ 稳健直线拟合（TLS 主方向 + 一轮离群剔除）→ 相邻边求交得角点
→ 位移/面积/凸性三重护栏，任一不过就退回粗定位的四点
```

两个细节值得单独记：

- **取最外侧的峰**：卡常有深色描边或内侧阴影，「描边→白底」那一跳比「桌面→卡边」强得多，
  直接取最大峰会让整张卡向内缩 2~8px。所以在「≥75% 峰值」的候选里取最靠外的一个。
- **定向必须在像素空间**：归一化坐标里 x/y 量纲被画幅比例缩放，16:9 的手机照片下一张 1.585 的
  横版卡会算成「竖版」，被误转 90° 拍扁。`orientPoints()` 因此只吃像素角点。

### 3.3 验收：纸白 + 字迹

`checkCrop()` 按四边形把卡面采样成 48×32 网格，取采样亮度 p90 作为**纸色估计**，±35 内算纸、
低于纸色 60 以上算字迹：

```
pass = paperFraction ≥ 0.65 && 0.004 ≤ inkFraction ≤ 0.55 && samples ≥ 200
```

固定阈值（爱印的 183）在偏黄/偏蓝的扫描件上会误杀，改成相对纸色后对底色不敏感；
「必须有字迹」这一条是挡「桌面纹理 + 阴影被当成卡」的关键——纯桌面能过纸色，但过不了字迹。

最终置信度 = `0.5·检测分 + 0.5·验收分`，UI 沿用 `NEED_CHECK = 0.6` 的门禁：
低于 0.6 不自动校正，保留原图并标「需检查」。

### 3.4 接线（`src/tools/CardLayout.tsx`）

- `loadImages()` 改为「一张图 → 1..N 条」：`detectCards()` 判定多卡时按 `decideCards()` 拆开，
  文件名追加 `（1/2）`、`（2/2）`；每条各自持有自己的 quad。
- 自动校正走 `warpToCorrected(..., { upright: true })`，按目标画幅把角点转 90°，不再把竖拍的卡拉扁。
- OCR 改为识别**已校正的卡面**（`corrected.dataUrl` 优先）：摆正裁净后文字更整齐，类型判得更准。

## 4. 门禁

| 命令 | 覆盖 |
|---|---|
| `npm test`（`src/lib/cardDetect.cv.test.ts`，12 项） | 正放 / 旋转 12° / 透视俯拍 / 满幅 / 低对比 / 竖拍 / 双卡拆分 / 单卡不误拆 / 无卡不编造 / 验收 / 重采样 |
| `npm run verify:card`（`tools/card_detect_smoke.py`，12 项） | 真浏览器端到端：PIL 合成翻拍照片 → 导入 → 断言卡数、置信度、校正图比例 1.585、四角是卡面白、卡内有字迹、双卡拆分标注、无卡回退、无 JS 报错 |

单测用「程序化拍照」而不是固定图片：把带抬头条/头像块/文字行的卡面用单应贴到带渐变的桌面上，
再叠噪声与模糊，真值四角可精确比对，误差能直接断言到像素（当前：正放 <4px、旋转 <6px、透视 <8px）。

性能：1280×960 工作分辨率下单张约 **85~95ms**（本机 Node，单遍检测；只有在结果不可靠时才跑第二遍
直方图均衡）。导入 50 张约 4~5 秒，分散在逐张 `await` 之间，不阻塞交互。

## 5. 还差什么

1. **模型级精度**：非凸/贴边/强反光的卡，模型的鲁棒性仍然更好。`cardDetect.ts` 的
   `CardCandidate` 结构就是给将来接 ONNX 角点模型留的位（`method` 字段可扩 `'model'`）。
2. **方向判定**：爱印用 OCR 的 `turns` 判 0/90/180/270；我们目前只做「横竖」这一档，
   倒着拍的卡需要用户在列表里点旋转。
3. **非证件矩形**：名片的圆角、护照的资料页、户口本的竖版内页，长宽比先验要按类型细分。
4. **批量并发**：单张 90ms 目前跑在主线程；要更顺可搬到 Worker（`warpWorker` 已有同款结构）。
